## 二、根因：为什么"很多歌没法播放 + 自动换源也救不了"

### 1. 默认源恰好是死的（主因）

`pickDefaultSourceFile()` 的规则是：文件名含 `default` 优先 → 其次 `qdy` → 最后第一个。

- 现在含 `default` 的只有 `default-changqing.js` —— 实测 0/5，返回 404。
- 就算去掉它，下一个会选中 `qdy.js` —— 也是死的（410）。
- 而 `bootstrap()` 又优先沿用 `S.lastApiId`（上次用的源），所以程序启动后大概率一直挂在死源上。

### 2. 自动换源只验"脚本能初始化"，不验"真能取到地址"

`autoSwitchSource()` 的核心：

```js
await lx.enable(a.id)
const ok = await lx.ready(12000)
if (ok) return a.name   // ← 到这里就认为"换源成功"了
```

`lx.ready()` 只代表脚本注册并初始化完成，**不代表上游接口活着**。
上面 4 个死源全都能通过这一步，于是：

- 4 次换源机会全部落在"能初始化但取不到地址/取到坏地址"的源上；
- 最后报"这首歌拿不到播放地址，几个音源都试过了"；
- 用户体感就是"明明有一堆源，就是不会自动跳到能用的那个"。

### 3. 健康分不惩罚"能初始化但取不到地址"的源

`markApi(a.id, false)` 只在**初始化失败**时调用；初始化成功就直接 `return`，不测 URL、不扣分。
结果：死源永远保持 0 分不降权，每次排序都还在候选里；真正能用的源反而可能排后面。

### 4. 用户目录混入已停用源

程序实际读取的是 `%APPDATA%\lx-music-desktop\sources`（打包版），当前有 **22 个文件**，比 `_sources/` 多出：

- `changqing.js`（与 `default-changqing.js` 内容重复）
- `huanyin.js`、`huibq.js`、`ikun.js`、`sixyin.js`（这些在开发目录早已移入 `_已停用/`）
- `my-source-示例模板.js`（返回固定测试音频，不该当正式源）

用户手动导入这些源，会再次踩到已判死的坑。

### 5. 高音质优先导致首播多失败一次

野花/野草只出 128k。若设置里音质选的是 320k/flac，会先失败一轮再回退 128k，首播变慢、也可能触发换源误判。

## 三、解决方案（按优先级）

### P0 · 立即清理（不改代码，马上见效）

1. `_sources/` 里 5 个死源移入 `_sources/_已停用/`：
   `default-changqing.js`、`hywmusic.js`、`lx.js`、`qdy.js`、`juhe.js`
2. 清理 `%APPDATA%\lx-music-desktop\sources`：
   - 移走上面 5 个死源
   - 移走 `changqing.js`（重复）、`huanyin.js`、`huibq.js`、`ikun.js`、`sixyin.js`
   - 示例模板改名加下划线（`_my-source-示例模板.js`）或移走
3. 重设默认源：把 `jiexiang.js` 改名为 `default-jiexiang.js`（**不能复制**，内容重复会被导入校验拒绝），同时去掉 `default-changqing.js` 的 default 前缀或移走。

### P1 · 修自动换源（核心代码改动）

`autoSwitchSource(reason, song)`：

1. 候选源 enable + ready 后，先查 `lx.current.sources[song.source]`：
   - 不支持该平台 → **跳过**（不计换源次数、不扣健康分）
2. **真取一次地址** `await lx.url(song, '128k')`：
   - 拿不到 / 抛错 → `markApi(a.id, false)`，继续下一个
   - 拿到 → `markApi(a.id, true)`，接受该源
3. `rankApis()` 排序前同样把"最近连续失败"的源沉底
4. 失败提示区分三种情况：
   - 所有源都不支持该平台
   - 支持但都取不到地址
   - 全部初始化失败

### P2 · 健康度可见 + 自检

1. 设置 → 音源页给每个源显示状态：`可用 / 疑似失效 / 初始化失败 / 卡密过期`
2. 加一个「检测当前音源」按钮：用一首内置样本歌取地址并探活，几秒出结果
3. `ensureUserSourceDir()` 目前「只补缺、不覆盖」——升级后用户目录里的旧内置源永远不会更新。
   建议：用内容 hash 对比，**未被用户修改过的旧文件自动覆盖**，改过的保留并备份。

### P3 · 音质策略

- 默认音质建议 128k（你这套源里有一批只出 128k）；想用高音质再手动切。
- 保留现有的"高音质失败自动回退 128k"逻辑。

### 清完死源后仍需注意的失败场景

1. **歌曲本身不在任何源的曲库**（下架/版权/VIP 独占）→ 所有源都取不到地址。
2. **换源逻辑不验证目标源是否真有这首歌**：`autoSwitchSource` 目前只验 `lx.ready()`；建议按 P1 改为「真取一次地址再接受」。
3. **推荐榜点播按「歌名+歌手」只取搜索结果第 1 条**：实测「海屿你」会匹配成「海屿你2.0」。不是放不出来，但会放错版本。
4. **本地文件被移动/删除** → 播不了。
