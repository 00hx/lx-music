## 三、三窗口架构（核心设计）

这是整个项目的骨架：**三个物理窗口，三种完全不同的安全配置**。

| | 主窗口 `persist:win-main` | 桌面歌词窗口 | 自定义音源窗口 |
|---|---|---|---|
| 载体 | `renderer/index.html` | `renderer-lyric/index.html` | `data:text/html` 内联串 |
| 分区 | `persist:win-main` + 独立代理 | 独立 | **无 partition**（每次切换源销毁重建） |
| nodeIntegration | ✅ true | ❌ | ❌ |
| contextIsolation | ❌ **false** | — | ✅ **true** |
| sandbox | false | — | false |
| webSecurity | ❌ false | — | — |
| preload | 无 | 无 | `user-api-preload.js` |
| webgl / images | webgl:false，spellcheck:false | — | webgl:false + **images:false** |
| 窗口 | `frame:false`、可透明、不可缩放、`resizable:false` | 无边框 + 鼠标穿透检测 | `show:false`、不可交互 |

**要点**：主窗口为了直接用 Node API 和本地文件，彻底关掉了隔离与安全策略——这是老项目典型形态，跟你在「咕咕嘎嘎」里走 preload + 桥接的路线是**两代思路**。

## 六、自定义音源沙箱（项目最有反汇编价值的部分）

用户导入的第三方音源脚本**不在主窗口执行**，而是塞进一个一次性隐藏窗口。链路：

```
用户粘贴脚本
  └─ renderer: importUserApi(text)
      └─ IPC winMain_import_user_api
          └─ main/modules/userApi/utils.ts
              ├─ parseScriptInfo()  正则 /^\/\*[\s\S]+?\*\// 解析头部注释
              │                     抽取 @name @description @author @homepage @version（各带长度上限）
              ├─ zlib.deflate → 'gz_' + base64   压缩后落 JSON store
              └─ 查重：脚本内容相同则抛「导入失败，脚本内容与已有的源相同」
  └─ renderer: setUserApi(id)
      └─ userApi/index.ts setApi() → 先 closeWindow() 销毁旧窗口 → loadApi(id)
          └─ main/modules/userApi/main.ts createWindow(userApi)
              ├─ new BrowserWindow( contextIsolation:true, nodeIntegration:false,
              │                     images:false, webgl:false, disableDialogs:true,
              │                     autoplayPolicy:'document-user-activation-required',
              │                     preload: user-api-preload.js )
              ├─ 拦截 5 个事件：will-navigate / will-redirect / will-attach-webview
              │                 / will-prevent-unload / media-started-playing → 全部 preventDefault
              ├─ setPermissionRequestHandler → 一律 resolve(false)
              ├─ setWindowOpenHandler      → 一律 deny
              └─ loadURL('data:text/html;charset=UTF-8,' + encodeURIComponent(html))
                  └─ ready-to-show 后 send initEnv { script, proxy, name, version... }
```

**preload 暴露给脚本的桥**（`renderer/preload.js`，12.5 KB）：

```js
contextBridge.exposeInMainWorld('lx', {
  EVENT_NAMES: { request, inited, updateAlert },
  request(url, {method, timeout, headers, body, form, formData}, cb) { ...needle... },
  send(eventName, data),      // inited / updateAlert
  on(eventName, handler),     // request
  utils: {
    crypto: { aesEncrypt, rsaEncrypt, randomBytes, md5 },
    buffer: { from, bufToString },
    zlib:   { inflate, deflate },
  },
  currentScriptInfo: { name, description, version, author, homepage, rawScript },
  version: '2.0.0',
  env: 'desktop',
})
```

**脚本能力白名单 + 出参校验**（安全边界都在这）：

| 校验点 | 规则 |
|---|---|
| 支持平台 | `kw / kg / tx / wy / mg / local`（`xm` 只在 actions 表里出现，未进 allSources） |
| 音质白名单 | `128k / 320k / flac / flac24bit`，且必须声明在 `supportQualitys` 内 |
| 动作白名单 | 在线平台仅 `musicUrl`；`local` 额外允许 `lyric` / `pic` |
| `musicUrl` 出参 | 必须 string、长度 ≤ 2048、且 `/^https?:/` |
| `lyric` 出参 | `lyric` ≤ 51200，`tlyric`/`rlyric` ≤ 5120，`lxlyric` ≤ 8192 |
| 请求超时 | 脚本侧 `min(timeout, 60000)`，主进程侧统一 20 s 硬超时 |
| 更新提示 | `updateAlert` 只能调一次，`log` ≤ 1024，`updateUrl` 正则校验 |
| 错误上报 | preload 注入 `window.onerror` + `unhandledrejection` 监听，回传主进程（各截断 1024） |

**请求回环**：渲染侧发 `winMain_request_user_api` → 主进程生成 `requestKey` 存 `requestQueue` + 20 s `setTimeout` → 转发进沙箱窗口 `userApi_request` → preload 调脚本 `events.request(...)` → 结果走 `userApi_response` 回主进程 → 按 `requestKey` resolve Promise。切换音源/移除音源时 `closeWindow()` 会 `clearAuthCache + clearStorageData + clearCache` 后 `destroy()`。

> **这一套是你 AI 逆向最该细读的地方**：导入即压缩存储、执行在一次性隔离窗口、能力靠白名单裁剪、出参三重校验。防护做得比大多数同类 Electron 项目认真。

## 八、数据落盘

### 8.1 SQLite（业务数据）

`src/main/worker/dbService/` 跑在 `worker_threads`，主进程通过 **Comlink** 调用（`comlink/dist/esm/node-adapter`）：

```ts
// main 侧
const worker = new Worker(new URL('../dbService', import.meta.url))
return Comlink.wrap<LX.WorkerDBSeriveListTypes>(nodeEndpoint(worker))
// worker 侧
exposeWorker({ ... })
```

**表结构**（`tables.ts`，`DB_VERSION = '2'`）：

| 表 | 用途 |
|---|---|
| `db_info` | 版本元数据 |
| `my_list` | 歌单 |
| `my_list_music_info` + `index_` | 歌单内歌曲 |
| `my_list_music_info_order` + `index_` | 歌单内排序（独立表，避免整表重排） |
| `music_info_other_source` + `index_` | 歌曲的"其他源"关联 |
| `lyric` | 歌词缓存 |
| `music_url` | 播放地址缓存 |
| `download_list` | 下载任务 |
| `dislike_list` | 不喜欢列表 |

`db.ts` 的健壮性设计：
- `fileMustExist: true` 首次打开 → 失败即建库建表
- `journal_mode = WAL`（故要一起备份 `-wal` / `-shm`）
- 老库先 `migrateData` → 再 `PRAGMA optimize` → 再 `verifyDB`
- 校验失败 → 主进程弹窗 → 把 `lx.data.db{,-wal,-shm}` `renameSync` 备份成 `.bak` → 重建
- `nativeBinding` 显式指向 `${__dirname}/../node_modules/better-sqlite3/build/Release/better_sqlite3.node`（打包后路径）

### 8.2 JSON Store（配置类）

`src/main/utils/store.ts` 自研 78 行 Store 类，无 electron-store 依赖：
- 落盘 `global.lxDataPath/<name>.json`
- **原子写**：先写 `<file>.<rand>.temp` → `renameSync`
- 解析失败 → 备份 `.bak` → 弹窗 + `shell.showItemInFolder`
- 已知 store：`USER_API`（自定义源清单）等

### 8.3 路径布局

```
%APPDATA%\lx-music-desktop\        # app.getPath('userData')
└─ LxDatas\                        # global.lxDataPath
   ├─ lx.data.db (+ -wal/-shm)     # SQLite
   └─ *.json                       # Store
```

Win 便携模式：exe 同目录存在 `portable/` 文件夹时 → `app.setPath('appData'|'userData')` 重定向到 `portable/userData`。

## 九、桌面歌词（独立窗口）

`src/main/modules/winLyric/` + `src/renderer-lyric/`（独立 webpack target、独立 store、独立 8 个组件）。

关键能力：
- `config.ts`：窗口尺寸/位置/字体/颜色/行距/透明度等全套配置项持久化
- `mouseCheckTools.ts`：**鼠标穿透**——非锁定态可交互，锁定态 `setIgnoreMouseEvents(true, {forward:true})` 并靠轮询命中检测恢复
- 与主窗口通过一对 IPC 事件握手：`winLyric_request_main_window_channel` ↔ `winLyric_provide_main_window_channel`
- 支持全屏自动隐藏、暂停隐藏、hover 隐藏、始终置顶（含"循环置顶"对抗其他窗口夺顶）
- 独立 `renderer-lyric/` 里还有自己的 `useApp/` 启动链和 `core/`

**这道工序值得你在「咕咕嘎嘎」里对照**——你现在的多会话浏览器是单窗口 + 多 webview，如果以后要做"独立小窗工具面板"，这份独立 target + IPC 握手的做法可以直接复用。

## 十、对外控制面（四条入口）

### 10.1 OpenAPI（内置 HTTP + SSE）

`src/main/modules/openApi/index.ts`，`http.createServer` + `node:querystring`：

| 路由 | 行为 |
|---|---|
| `GET /status?filter=a,b` | 播放状态 JSON，字段可过滤（默认 status/name/singer/albumName/lyricLineText/duration/progress/playbackRate） |
| `GET /lyric` / `/lyric-all` | 当前歌词 / 全量四轨歌词 |
| `GET /subscribe-player-status` | **SSE**，`event: <key>\ndata: <json>\n\n` 逐字段推送 |
| `/play` `/pause` `/skip-next` `/skip-prev` `/collect` `/uncollect` | 播放控制（转发成任务栏按钮点击） |
| `/seek?offset=` `/volume?volume=` `/mute?mute=` | 带参数校验，非法返回 400 |
| 其他 | 401 Forbidden |

- 响应统一带 `Access-Control-Allow-Origin: *`
- socket `setTimeout(4000)`，关闭服务时遍历 `sockets` 强制 destroy
- `bindLan` 决定监听 `0.0.0.0` 还是 `127.0.0.1`
- 推流是拉模式：`global.lx.event_app.on('player_status', sendStatus)`，只在有订阅者（`responses.size`）时才写

### 10.2 数据同步

`src/main/modules/sync/` 同时实现两端：
- `client/`：`listEvent.ts`（歌单同步，7.4 KB）、`dislikeEvent.ts`、`migrate.ts`、`log.ts`
- `server/`：本机作为同步服务端（配 `sync.server.port`、`sync.server.maxSsnapshotNum` 保留快照数）
- 协议类型在 `src/common/types/sync*.d.ts`，另有 `sync_common.d.ts`

### 10.3 Scheme URL

`app.setAsDefaultProtocolClient('lxmusic')`；dev 模式下额外传 `process.execPath` + `process.argv.slice(1)`（Windows 特有）。
- macOS 走 `app.on('open-url')`
- Windows/Linux 走 `second-instance` 的 argv 解析
- 已运行时 `global.lx.event_app.deeplink(url)` 直接派发，未运行则 `startApp()`
- `URL_SCHEME_RXP` 先做白名单校验再放行

### 10.4 全局快捷键 / 托盘 / 任务栏

- `hotKey/`：`local`（窗口内）+ `global`（系统级）两套配置，`global.lx.hotKey.state` 是 `Map`
- `tray.ts`（12 KB）：主题化托盘图标、菜单、`isSkipTrayQuit` 标志控制"关窗口"是隐藏还是退出

## 十二、关键设计取舍

**做得好的**
1. IPC 名称单一真源 + 三层封装，新增通道零心智负担
2. SQLite 独立 worker_threads + Comlink，主进程不被阻塞；表设计把"排序"拆独立表
3. 自定义源沙箱：隔离窗口 + 白名单 + 出参三重校验 + 错误兜底上报，工程完整度罕见
4. 原子写 JSON、WAL + migrate + verifyDB、失败自动备份并弹窗，数据层很少翻车
5. 打包目标矩阵脚本化，Win7/arm64/多发行版格式全覆盖

**技术债 / 风险点**
1. 主窗口 `contextIsolation:false` + `nodeIntegration:true` + `webSecurity:false` —— 现代 Electron 明确不推荐，但项目已定型难改
2. 目录名 `src/renderer/utils/ipc.ts` 这个"门面"膨胀到 29 KB / 100+ 导出
3. `src/renderer/views` 119 个 + `store` 47 个，耦合度较高，无类型化 store
4. Electron 42 而对原生模块用固定 `nativeBinding` 路径 + 预编译 `.node`（`build-config/lib/better_sqlite3_*.node`），换版本/换 ABI 需手工替换
5. devDependency 里一堆 `github:lyswhut/*` fork（needle、eslint-formatter-friendly、spinnies、webpack-hot-middleware、electron-devtools-installer）——跟主版本兼容风险自负

## 十四、与「咕咕嘎嘎」的对照（可直接吸收的点）

| 维度 | LX Music 做法 | 对「咕咕嘎嘎」的价值 |
|---|---|---|
| 多窗口 | 三窗口三套 webPreferences + 独立 webpack target | 若加独立小窗，复用其 target 拆分 + IPC 握手 |
| 会话隔离 | `session.fromPartition('persist:win-main')` + `setProxy` 按 session 设 | 你的 webview partition 方案一致，可借鉴它的**代理按 session 下发** |
| 窗口打开策略 | `will-navigate` 白名单 + `setWindowOpenHandler` → `shell.openExternal` | 你的 `allowpopups` 是反面案例（它反而全 deny），两条路各有取舍 |
| IPC 组织 | ipcNames 单一真源 + 三层层封装 | **最值得直接抄**，你现在还在散落 `ipcMain.handle` |
| 数据层 | SQLite 跑 worker_threads + Comlink | 你现在用 JSON，量大了可平滑迁移 |
| 外控面 | HTTP + SSE + Scheme URL | 做自动化/联动（如让脚本控制浏览器）可照抄 SSE 推流模式 |
| UA/风控 | 本项目未做（纯本地请求） | 你在抖音风控上的 `setUserAgent` 是它没有的实战经验 |
