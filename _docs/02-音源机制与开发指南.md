# 音源机制与开发指南

> 基于 `lx-music-desktop` v2.12.5 源码实测整理，所有路径均相对项目根目录。

---

## 零、三句话看懂接口（通俗版）

接口就是**插口**。就像 U 盘插电脑——插口形状、几根针、每根针干什么，事先定死。U 盘不用懂电脑内部，电脑也不用懂 U 盘里存了什么，**只要针脚对上就能用**。

音源和 LX 之间也是这么个插口，而且**整个插口上只有 3 根针**：

| 针 | 名字 | 谁对谁说 | 内容 | 频率 |
|---|---|---|---|---|
| ① | `inited` | 音源 → LX | 「我上线了，我叫 XX，我管酷我和酷狗」 | 一辈子一次 |
| ② | `request` | LX → 音源 | 「要酷我这首歌的地址，音质 320k」 | 每首歌一次 |
| ③ | `return` | 音源 → LX | 「拿去：`http://...mp3`」 | 每首歌一次 |

代码里就是这 7 行：

```js
const lx = window.lx          // LX 递进来的插口，脚本一启动就有

// ① 上线报到
lx.send('inited', {
  sources: { kw: { type: 'music', actions: ['musicUrl'], qualitys: ['320k'] } },
})

// ② LX 来要地址
lx.on('request', ({ source, action, info }) => {
  // ③ 把地址还回去
  return 'https://我的服务器.com/xxx.mp3'
})
```

三个关键认知：

1. **`window.lx` 不是脚本自己造的，是 LX 塞进去的**。LX 把脚本关进一个空窗口，预先在窗口里挂好 `window.lx`，然后才执行脚本。这根"线"由 LX 铺，音源只管用。
2. **是音源主动报到，不是 LX 去问**。因为 LX 不知道脚本何时加载完，让脚本自己说"我准备好了"最省事——这就是第 ① 根针存在的理由。
3. **`window.lx` 就是那根 USB 线，两头各接一个**。音源这头是 `send` / `on` / `return`，LX 那头是 `preload.js` 里的实现。两边内部怎么跑互相不关心，只管传这三句话。

> 想验证：打开 `../_sources/juhe.js`，20 行明文，直接能找到这三根针——`y(n.inited, U.init)` / `on(n.request, ...)` / `return B.data.url`（`y` 就是 `send`，`n` 就是 `EVENT_NAMES`）。

## 一、音源是什么

LX Music 自己不存歌、不托管歌。它手里只有一个歌曲编号，真正能播的 `http(s)` 地址得去平台要。

**负责"去要地址"的那层适配器，就是音源。**

统一契约只有一个方法：

```ts
apis(source).getMusicUrl(songInfo, quality) → { promise, canceleFn }
// promise 解析出 { type: '320k', url: 'https://...' }
```

业务代码永远只认这个门面，不认背后是谁实现的。

## 二、两类音源

| | 内置音源 | 自定义音源 |
|---|---|---|
| 代码位置 | `src/renderer/utils/musicSdk/<平台>/` | 用户导入的 `.js` 脚本 |
| 运行位置 | 主渲染进程（`nodeIntegration: true`） | 一次性隐藏窗口 + `contextIsolation: true` |
| 提供方 | 项目自带 | 用户 / 社区作者 |
| 随版本升级 | 是 | 否，靠用户手动更新 |
| 能力范围 | 搜索 / 榜单 / 歌单 / 歌词 / 封面 / 评论 全套 | **在线平台只放行 `musicUrl`** |
| 主开关 | `common.apiSource` 单选 | 同一个开关 |

**最容易误解的一点**：在线平台的 `actions` 白名单里只有 `musicUrl`，只有 `local` 才额外放 `lyric` / `pic`。所以——

> 自定义源**救不了「搜不到歌」**。搜索、榜单、歌单永远走内置 SDK。自定义源只解决「搜到了但点播放失败」。

## 三、音源从哪来（四条路径）

### 1. 内置音源（写死）
`src/renderer/utils/musicSdk/index.js` 里注册：

```js
const sources = {
  sources: [
    { name: '酷我音乐', id: 'kw' },
    { name: '酷狗音乐', id: 'kg' },
    { name: 'QQ音乐',  id: 'tx' },
    { name: '网易音乐', id: 'wy' },
    { name: '咪咕音乐', id: 'mg' },
    { name: '虾米音乐', id: 'xm' },
    // { name: '百度音乐', id: 'bd' },   ← 已注释
  ],
  kw, kg, tx, wy, mg, bd, xm,
}
```

每个平台目录下约 12 个模块：`musicSearch / leaderboard / songList / lyric / pic / comment / hotSearch / tipSearch / album / util / index`。

`xm` 虽在列表里，但在 `searchMusic()` 的 `excludeSource = ['xm']` 中被排除。

### 2. 本地文件导入
界面：`src/renderer/views/Setting/components/UserApiModal.vue`
流程：`$dialog` 选文件 → `readFile` → `importUserApi(script)`

### 3. 在线 URL 导入
界面：`src/renderer/views/Setting/components/UserApiOnlineImportModal.vue`
流程：`httpFetch(url, { follow_max: 3 })` 拉全文 → 校验 → `importUserApi(script)`

**硬限制：脚本内容上限 `9_000_000` 字节**，超了直接拒绝。

### 4. 官方预置源 —— 空的

```ts
// src/main/modules/userApi/config/index.ts
export const userApis: LX.UserApi.UserApiInfoFull[] = []

// src/renderer/utils/musicSdk/api-source-info.ts
const sources = []   // 只剩被注释掉的示例
```

**两个数组都是空的。** 这不是遗漏，是合规边界：官方只提供插槽，脚本由用户自己找、自己导入。

> 注：`api-source-info.ts` **不是自定义源清单**，它是内置接口的多实现切换位（轮换域名、灰度用），entry 里带 `supportQualitys`，配套的 `allApi` 目前是空对象。别搞混。

## 四、导入与存储

全部在 `src/main/modules/userApi/utils.ts`：

```
parseScriptInfo(scriptRaw)   // 必须能匹配开头的块注释
      ↓
deflateScript(scriptRaw)     // zlib.deflate → base64 → 前缀 'gz_'
      ↓
存入 STORE_NAMES.USER_API
```

### 注释头解析
- 整体匹配：`/^\/\*[\S|\s]+?\*\//`，**匹配不到就抛「无效的自定义源文件」**
- 逐行取字段：`/^\s?\*\s?@(\w+)\s(.+)$/`
- 长度上限（超长截断加 `...`）：

| 字段 | 上限 |
|---|---|
| `@name` | 24 |
| `@description` | 36 |
| `@author` | 56 |
| `@version` | 36 |
| `@homepage` | 1024 |

`@name` 为空时回落成 `user_api_<日期时间>`。

### 存储细节
- 落盘文件：`%APPDATA%\lx-music-desktop\LxDatas\user_api.json`
  （`STORE_NAMES.USER_API = 'user_api'`，路径由 `src/main/utils/store.ts` 拼 `lxDataPath + name + '.json'`）
- 写入方式：temp 文件 + `fs.renameSync` 原子替换
- id 格式：`user_api_<3位随机>_<Date.now()>`
- 去重：deflate 结果完全相同的脚本会被拒绝导入
- `inflateScript()` 对**非 `gz_` 前缀**的字符串原样返回 → **预置源可以直接写明文脚本**

### ⚠️ 预置源的注入坑

```ts
let infoFull = store.get('userApis')
if (infoFull) { /* 用存储里的 */ }
else { infoFull = defaultUserApis; ... }
```

`if (infoFull)` —— **空数组 `[]` 也是 truthy**。所以：

- 全新安装、首次启动 → 注入预置源 ✓
- 用户导入过或删除过源（触发 `saveData()` 写入数组）→ 此后**再也不注入预置源** ✗

想让预置源「删了还能回来」，得自己改这个判断，比如改成 `Array.isArray(infoFull) && infoFull.length`，或者给内置源加标记做合并。

## 五、运行契约

全部来自 `src/main/modules/userApi/renderer/preload.js`，`version = '2.0.0'`，`env = 'desktop'`。

### 5.1 全局对象

脚本里只能看到 `window.lx`，内容如下（`contextBridge` 白名单，`require` / `fs` / `process` 一律不可见）：

| 成员 | 说明 |
|---|---|
| `EVENT_NAMES` | `{ request, inited, updateAlert }` |
| `request(url, opts, cb)` | HTTP 请求，返回 abort 函数 |
| `send(name, data)` | 只认 `inited` / `updateAlert` |
| `on(name, handler)` | 只认 `request` |
| `utils.crypto` | `aesEncrypt` / `rsaEncrypt` / `randomBytes` / `md5` |
| `utils.buffer` | `from` / `bufToString` |
| `utils.zlib` | `inflate` / `deflate`（均返回 Promise） |
| `currentScriptInfo` | `{ name, description, version, author, homepage, rawScript }` |
| `version` | `'2.0.0'` |
| `env` | `'desktop'` |

### 5.2 事件

| 事件 | 方向 | 次数限制 |
|---|---|---|
| `on(EVENT_NAMES.request, handler)` | 被调用 | 覆盖式赋值，只能挂一个 |
| `send(EVENT_NAMES.inited, info)` | 上报 | **只能调一次**，不调则一直等，最后弹「初始化失败」 |
| `send(EVENT_NAMES.updateAlert, { log, updateUrl })` | 上报 | **只能调一次**，`log` 上限 1024 字符 |

### 5.3 request()

```js
request(url, {
  method,       // 'get' / 'post' ...
  timeout,      // 上限被裁到 60000ms，默认 60000
  headers,      // 对象
  body,         // JSON 体
  form,         // 表单（会自动 json=false）
  formData,     // multipart（会自动 json=false）
}, (err, resp, body) => {})
```

`resp` 结构：`{ statusCode, statusMessage, headers, bytes, raw, body }`
`body` 会被自动 `JSON.parse` 一次，解析失败则保留原始字符串。

### 5.4 能力白名单（硬编码在 preload 里）

```
allSources     = ['kw','kg','tx','wy','mg','local']
supportActions = { kw:['musicUrl'], kg:['musicUrl'], tx:['musicUrl'],
                   wy:['musicUrl'], mg:['musicUrl'], xm:['musicUrl'],
                   local:['musicUrl','lyric','pic'] }
supportQualitys= { kw/kg/tx/wy/mg: ['128k','320k','flac','flac24bit'], local: [] }
```

脚本在 `send(inited, ...)` 里声明的 `sources`，会和上面这份白名单**取交集**，交集外静默裁掉。

> 注意：`allSources` 循环里**不含 `xm`**，所以虾米声明了也装不进去。

### 5.5 出参校验（不通过就是 `failed`，不告诉你细节）

| action | 校验规则 |
|---|---|
| `musicUrl` | 必须是 string、长度 ≤ **2048**、必须 `/^https?:/` |
| `pic` | 同上 |
| `lyric` | 必须是 object 且 `lyric` 是 string；`lyric` ≤ **51200**；`tlyric` / `rlyric` < **5120**；`lxlyric` < **8192** |

### 5.6 沙箱窗口配置

`src/main/modules/userApi/main.ts`：

- `contextIsolation: true` / `nodeIntegration: false` / `sandbox: false`
- `images: false` / `webgl: false` / `enableWebSQL: false` / `disableDialogs: true` / `spellcheck: false`
- 页面用 `loadURL('data:text/html;charset=UTF-8,' + encodeURIComponent(html))` 加载
- 拦截事件：`will-navigate` / `will-redirect` / `will-attach-webview` / `will-prevent-unload` / `media-started-playing`
- 权限请求一律 `resolve(false)`；`setWindowOpenHandler` 一律 `deny`
- 关窗口时清 `clearAuthCache` + `clearStorageData` + `clearCache` 后 `destroy`

## 六、调度链路

### 渲染层分叉
`src/renderer/core/apiSource.ts` → `setUserApi(apiId)`：

```ts
if (/^user_api/.test(apiId)) {
  // 自定义源：走 store.userApi.apis，由 IPC 转发到沙箱窗口
} else {
  // 内置源：qualityList = musicSdk.supportQuality[apiId]
}
```

**`/^user_api/` 这个 id 前缀是全项目的分叉依据**，`musicSdk/api-source.js` 里也是同一套判断。

### 动态合成 API
`src/renderer/core/useApp/useInitUserApi.ts` 监听 `onUserApiStatus`，按脚本声明的 `actions` 现造方法：

| 声明 | 生成的方法 |
|---|---|
| `musicUrl` | `apis[source].getMusicUrl(songInfo, type)` |
| `lyric` | `apis[source].getLyric(songInfo)` |
| `pic` | `apis[source].getPic(songInfo)` |

每个都返回 `{ promise, canceleFn }` 形状，与内置音源接口对齐。

### 完整链路
```
用户点播放
  → core/music 调 apis(source).getMusicUrl(songInfo, quality)
      ├─ 内置源：musicSdk/<平台>/musicUrl 实现，直接 httpFetch 平台接口
      └─ 自定义源：userApi.apis[source].getMusicUrl
            → IPC(requestKey + data)
            → 沙箱窗口 preload 的 handleRequest
            → 调脚本注册的 events.request({ source, action, info })
            → 出参校验
            → IPC(response, requestKey) 回传
  → 播放器拿到 url
```

切换音源时用 `requestKey` 做取消，20 秒硬超时。

## 七、二次开发三条路

### ① 写自定义源脚本（成本最低）
不动源码，写一个带注释头的 `.js`，界面导入。只接管 `musicUrl`。

模板见 `../_sources/my-source.js`。

四条硬规矩：
1. `/*! ... */` 注释头必须有
2. 必须 `send(EVENT_NAMES.inited, {...})`
3. 返回的 URL 必须 `http(s)` 且 ≤2048
4. 能力要按白名单申报

### ② 预置源自带打包（改 1 个文件）
改 `src/main/modules/userApi/config/index.ts`，往 `userApis` 数组里塞 `UserApiInfoFull` 对象，`script` 字段写明文即可。

**注意第四节那个 truthy 坑。**

### ③ 改内置源码 / 加新平台（大工程）
要加一个平台（比如 B 站音频），需三处改动：
1. `src/renderer/utils/musicSdk/<新id>/` 实现全套 12 个模块
2. `src/renderer/utils/musicSdk/index.js` 的 `sources` 数组注册
3. `src/renderer/utils/musicSdk/api-source-info.ts` 补 `supportQualitys`

**只有一种情况值得走**：用自己的音频服务顶替内置平台的 `getMusicUrl`。那也不用全改，只动 `musicSdk/<平台>/index.js` 里的 `getMusicUrl()` 一个方法就够——它本体就是一行转发：

```js
getMusicUrl(songInfo, type) {
  return apis('kw').getMusicUrl(songInfo, type)
}
```

## 八、进阶：服务端下发能力声明

`_sources/juhe.js`（972 字节，完全明文）演示了一个比本地写死 `sources` 灵活得多的模式：

```js
// 1. 拉配置
h(A + '/init.conf').then(r => {
  const U = r.body.data
  // 2. 版本比较，决定是否提示更新
  if (U.update.version > v) y(n.updateAlert, U.update)
  // 3. 能力声明由服务端下发
  y(n.inited, U.init)
})

// 4. 请求转发
on(n.request, async ({ action, source, info }) => {
  const r = await h(`${A}/${source}`, { method: 'POST', body: t(info), ... })
  // 支持 303 二次跳转协议
})
```

**优点**：改服务端就能增删平台、音质、换上游，**不用重新分发脚本**。

它还实现了 `code === 303` 的二次跳转：服务端返回 `{ request: {url, options}, response: { check: {key, value}, url } }`，脚本发起第二跳，用 `check.key.reduce(...)` 逐层取值校验后再从 `response.url` 路径拿结果。这套设计适合做「多链路自动回退」。

自建源优先用这个模式。

## 九、坑清单

| 坑 | 现象 | 应对 |
|---|---|---|
| 无注释头 | 导入报「无效的自定义源文件」 | 保证文件以 `/*! ... */` 开头 |
| 忘记 `send(inited)` | 源一直「初始化中」，最后弹失败 | 脚本末尾必须调 |
| URL 超 2048 | 播放直接 failed，无任何提示 | 用短链或中转 |
| 在线导入超 9MB | 拒绝导入 | 拆分或本地导入 |
| 只勾选不导入 / 只导入不勾选 | 源列表里有但不生效 | 导入后必须回上层下拉里选中 |
| 预置源不生效 | 用户动过源列表后新装版本看不到预置源 | 见第四节 truthy 坑 |
| 混淆源不可审计 | 跑在能发请求、能调加密的沙箱里 | 优先用明文源；`juhe.js` 可作范本 |
| 音源集体失效 | 平台接口变更，全平台播放失败 | 回音源仓库拿最新 `latest.js` 替换 |
