# 03 · 界面逻辑层说明

界面本体是 `src/renderer/index.html`（lizi 提供的单文件「Void Nebula — 螺旋星尘」，含 three.js 粒子背景，样式与画面脚本全部内联）。
**所有行为逻辑集中在 `src/renderer/app.js`**，由 webpack 打包成 `dist/renderer.js`，自动注入到 `dist/index.html` 的 `</body>` 前。

---

## 一、构建关系

| 文件 | 角色 |
|---|---|
| `src/renderer/index.html` | 界面本体（HTML + CSS + three.js 粒子），**不含业务逻辑** |
| `src/renderer/app.js` | 界面逻辑层（webpack entry → `dist/renderer.js`） |
| `src/static/qdy-source.txt` | 默认音源脚本（`.txt` 后缀刻意为之，见「踩坑」） |
| `src/static/sources/*.txt` | 6 个备选音源，在设置面板里可随时导入切换 |
| `build-config/renderer/webpack.config.base.js` | entry 指向 app.js，`HTMLPlugin.inject: 'body'` |

重新编译界面：

```bash
npm run build:renderer          # 产出 dist/index.html + dist/renderer.js
```

启动应用：双击项目根目录的 `start.cmd`。

---

## 二、app.js 的四大块

| 段 | 内容 |
|---|---|
| **音源层 `lx`** | 通过 IPC 调主进程的自定义音源沙箱：导入 / 启用 / 删除 / 取播放地址 |
| **播放核心 `P`** | `<audio>` + 播放队列 + 播放模式（原本在已删除的 Vue 渲染层，这里重建） |
| **界面接管** | 底部控制条 15 个控件、进度条拖拽、键盘快捷键 |
| **设置面板** | 右上角房子按钮打开：音源 / 队列 / 控制 / 界面 四页 |

状态用 `localStorage`（键 `lx-ui-state-v1`）持久化：队列、当前曲目、播放模式、音质、音量、收藏、睡眠定时、界面参数。

调试时可在控制台用 `window.lxApp` 拿到全部内部对象：`{ S, P, lx, ACT, audio, openPanel, closePanel }`。

## 五、播放链路

```
点播放键
  → P.playIndex(index)
      → lx.ready()                 等音源就绪（主进程会回 user_api_status）
      → lx.url(song, quality)      IPC → 主进程 → 沙箱窗口跑音源脚本 → 返回 http(s) 地址
      → audio.src = url            （拿不到就回退 128k 再试一次）
      → audio.play()
      → loadLyric(song)            并发取歌词 + 封面
  → timeupdate 更新进度条与时间

取歌词：https://m.kuwo.cn/newh5/singles/songinfoandlrc?musicId=<songmid>
        失败重试 3 次（该接口多节点数据不一致，同一个 id 有时返回 data:null）
封面：同一接口里的 songinfo.pic
```

请求都走 **Node 的 http/https 模块**（`httpGet()`），不是页面的 `fetch`——原因见下。

## 七、踩过的坑（改代码前先读）

**1. 音源脚本不能叫 `.js`**
`src/static/` 下的 `.js` 会被 webpack 的 CopyPlugin 一起压缩，开头 `/*! @name ... */` 注释头被删掉，导入后源名会变成 `user_api_<日期>` 这种兜底名。所以一律用 `.txt` 后缀（`qdy-source.txt`、`sources/*.txt`），CopyPlugin 就只 `[copied]` 不处理。

**2. 页面重载后必须重新启用音源**
主进程的音源在渲染层重载后会处于「未加载」状态，直接请求会报 `user api is not load`。`lx.bootstrap()` 每次页面加载都会 `enable` 一次（`enable()` 内部对「已经是当前源且状态 ok」做了幂等跳过）。

**3. 坏源判定不能急**
`audio.play()` 在 `src` 刚设上的瞬间会偶发 `NotSupportedError`，此时资源其实马上就绪。`handleBadSource()` 的做法是：等 2.5 秒 → 只认 `audio.error` 这个硬指标（为 null 就是抖动）→ `readyState >= 2` 则放过 → 真正失败时**先原地重取一次地址**（聚合音源内部多条链路，重取命中率高）→ 仍失败才换下一首。用 `badCount` 做保险丝、`badCooldown` 防无限跳。
（曾因只等 1.3 秒且不看 `audio.error`，把正常播放误判成坏源，连着跳掉两首歌。）

**4. `createMediaElementSource` 是不可逆的**
空间音频一旦启用，audio 的输出就永久经由 Web Audio 图；若此时 `AudioContext` 处于 `suspended`，声音会直接消失。所以必须**先 `resume()` 并确认 `state === 'running'`，再建立链路**，拿不到 running 就放弃启用并回退开关状态。播放时也补一次 resume。

**5. 自动播放策略**
合成的 `element.click()` 不算用户手势，Chromium 会拒掉 `audio.play()`。写自动化验证时，`executeJavaScript(code, true)` 的第二个参数 `userGesture` 必须传 true；真实用户点击不受影响。

**6. 酷我接口需要 UA / Referer**
用页面的 `fetch` 请求 `m.kuwo.cn` 会拿到 `{"data":null,"msg":"音乐查询失败"}`（Chromium 不允许脚本改 User-Agent）。改走 Node 的 `https` 并自行带 UA + Referer 即可。

**7. 歌词接口不稳定**
同一 `musicId` 有时返回完整 `lrclist`，有时返回 `data:null`（多节点数据不一致）。已做 3 次重试；个别歌确实取不到，界面显示「暂无歌词」属正常。
