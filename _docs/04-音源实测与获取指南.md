## 二、怎么测的（方法很重要，否则结论不可信）

工具：`_docs/tools/test-sources.js`

```
导入全部音源 → 逐个启用 → 等初始化 → 对多首酷我歌曲要地址
             → 依次试 320k / 128k → 对拿到的地址真发一个 HTTP Range 请求
```

四个关键点，都是踩过坑才补上的：

1. **必须真去拉一下地址**。`musicUrl` 返回非 null ≠ 能播 —— 地址可能是 403/404/410/过期的，界面上表现为"播放出错"。只有实际发请求拿到音频字节才算数。
2. **HTTP 探测必须跟随 301/302 跳转**（最多 5 跳）。播放器会跟，不跟会把好地址误判成坏的。
   > 这条吃过亏：第一轮测试里「长青SVIP」全军覆没、全返回 301 —— 我差点把它删掉。补上跳转跟随之后，它是表现最好的一个（3 轮 × 5 首 × 2 音质全过）。
3. **一次性导入全部源再逐个启用**。边测边导入时，启动阶段已自动导入的默认源会因「脚本内容重复」被主进程拒绝 —— qdy 第一轮就是这么漏测的。
4. **失败要重试一次，并且给单源设时间预算**。音源侧抖动很常见；而一个全挂的源会因为主进程 20 秒硬超时吃掉好几分钟，把整轮测试拖垮。

另外：测试跑在**隔离的用户数据目录**里，不碰你正在用的配置。

## 四、为什么是这些被淘汰

音源失效的样子有好几种，看错误信息能分辨：

| 症状 | 错误信息 | 含义 |
|---|---|---|
| 域名没了 | `getaddrinfo ENOTFOUND xxx.com` | 作者的接口域名已解析不了 → **死透了**（幻音 `music-dl.sayqz.com`、ikun `api.ikunshare.com`） |
| 接口通了但报错 | `Error: unknow error` / `Error: failed` | 作者的中间层挂了或改了协议（Huibq、六音） |
| 地址拿到了但打不开 | HTTP 404 / 410 / 返回 HTML | 拿到的直链是坏的（Hei Music） |
| 部分歌曲不行 | 个别歌 HTTP 410 | 该源对某些歌没有资源（非常刀 / 裤佬SVIP / 西瓜聚合：晴天） |

关于**六音**：它名气最大、文件也最大（333KB），但这次 **3 轮 × 5 首 × 2 音质全部失败**。它在今天早些时候还能用 —— 属于典型的"时好时坏"。文件留在 `_已停用/`，过些天可以重测。

## 五、以后怎么再拿新音源

### 5.1 最省事：面板里点 ⤓

设置面板 →「音源」页 → 拉到底部**「在线音源」**，一共 16 条（就是上面那份推荐清单），点一下自动下载 + 导入 + 启用。

- 下载失败会自动切换线路：直连 → `ghproxy.net` → `gh-proxy.com` → `ghfast.top`
- 点第二次 = 更新到最新版（会先删掉同名的再装，不会堆重复）

### 5.2 已经有链接：面板里「从链接导入」

粘贴一个 `.js` 的直链即可。**如果直连 GitHub 打不开，在地址前面拼镜像前缀**：

```
https://ghproxy.net/https://raw.githubusercontent.com/作者/仓库/main/xxx/latest.js
```

### 5.4 国内 Git 镜像站（不依赖 GitHub）

- `gitcode.com/gh_mirrors/lx/lxmusic-source-all` —— 收录 **22 个**开源音源
- `gitcode.com/gh_mirrors/lx/lxmusic-` —— 就是 `guoyue2010/lxmusic-` 的镜像

取文件走 `raw.` 前缀，例如：

```
https://raw.gitcode.com/gh_mirrors/lx/lxmusic-source-all/raw/main/README.md
```

> ⚠️ `gitcode.com` 的**网页**被 WAF 挡着（非浏览器请求返回 HTTP 418），API 也无法列目录，所以只能**按已知文件名直取**，不能浏览。

### 5.5 一次把某个仓库的源全拉到本地

```bash
node _docs/tools/fetch-sources.js
```

改脚本顶部的 `LIST` 数组即可（`[本地文件名, 仓库, 分支, 仓库内路径]`）。

## 六、以后自己复核（音源会失效，这是常态）

```bash
# 全量测一遍当前音源库（默认 5 首歌 × 320k+128k，单源预算 90 秒）
node _docs/tools/test-sources.js

# 只测某几个、或跑多轮看稳定性
node _docs/tools/test-sources.js --only=default-changqing.js,molan.js --rounds=3

# 测候选目录（先放在 _sources/_candidates/ 之类的地方，别直接混进正式库）
node _docs/tools/test-sources.js --dir=_sources-candidates --songs=3 --bail=2
```

脚本会在项目根生成 `_source-report.json`（含每首歌的地址与 HTTP 结果）。参数说明见脚本头部注释。

## 七、目录约定

```
_sources/                     面板「音源目录」扫的就是这里，顶层 .js 会列出来
├── default-changqing.js      默认源（文件名含 default，新建配置时优先用）
├── molan.js / kxh.js / ...   其余 15 个可用源
├── my-source-示例模板.js      写自己的音源时的骨架（返回 mock 地址，别当正式源用）
├── README.md
└── _已停用/                   失效的源留档，**面板不显示**（只扫顶层）
    └── huanyin.js, sixyin.js, ikun.js, huibq.js, ...

src/static/sources/           随安装包分发的内置源（同一批，.txt 后缀躲开 webpack 压缩）
```

打包运行时，程序会把内置源复制到 `%APPDATA%\lx-music-desktop\sources\`（那才是面板实际读的目录，因为 asar 内只读）。
